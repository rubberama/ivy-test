# 나에게 맞는 아이비리그는? — 성향 매칭 테스트

18개 질문에 답하면 아이비리그 8개교 중 결이 맞는 학교 세 곳을 매칭 적합도와 함께 알려주는 한 페이지 웹 테스트입니다. 한국에서 유행하는 "유형테스트" 포맷을 따랐습니다.

**두 가지 모드**가 있고, 시작 전에 누가 답하는지 고릅니다.

| 모드 | 대상 | 질문 형태 |
|---|---|---|
| 학생 | 17~21세 본인 | "개강 첫 주, 시간표를 짜는 나는" |
| 학부모 | 아이를 떠올리며 답하는 보호자 | "아이가 무엇을 배울지 정할 때 보면" |

두 모드는 **문구만 다르고 가중치와 채점은 완전히 같습니다.** 같은 선택지를 고르면 같은 학교가 같은 퍼센트로 나옵니다. 학부모 모드에서는 결과에 재정지원·환경·졸업 후 정보가 추가로 붙습니다.

> **이건 성향 매칭이지 합격 예측이 아닙니다.** 성적·시험 점수·스펙을 묻는 질문은 하나도 없고, 합격 가능성을 추정하지도 않습니다.

## 실행

빌드 과정이 없습니다. 둘 중 아무거나 하면 됩니다.

```bash
# 1. 그냥 파일을 더블클릭 (file:// 로 열림)
open index.html

# 2. 로컬 서버 (공유 링크 기능까지 쓰려면 이쪽)
python3 -m http.server 8000
```

`file://` 로 열어도 전부 동작합니다. 단 결과 **링크 공유**만 비활성화됩니다 (`file:///Users/...` 주소는 남에게 보내도 안 열리니까요). `js/share.js` 의 `SITE_URL` 에 배포 주소를 넣어두면 그 경우에도 켜집니다.

## 배포

정적 파일뿐이라 빌드 없이 그대로 올라갑니다.

### Vercel (권장)

1. [vercel.com/new](https://vercel.com/new) → GitHub 연결 → 이 저장소 Import
2. **Framework Preset: Other**, **Build Command 비움**, **Output Directory 비움**(루트)
3. Deploy

#### vercel.json 에 대해

캐시·보안 헤더가 들어 있습니다.

- **HTML·CSS·JS 는 `max-age=0, must-revalidate`** — 파일명에 해시가 없어서 오래 캐시하면 수정해도 예전 화면이 남습니다. ETag 로 304 를 받으므로 실제 전송량은 거의 없습니다.
  `cleanUrls: true` 때문에 사람이 실제로 여는 주소(`/`, `/korea-uni`)에는 확장자가 없습니다. `/(.*).(html|css|js)` 규칙은 확장자를 요구해서 이 둘에 안 걸리므로, 두 경로를 따로 적어둡니다. 규칙을 늘릴 때 같이 챙기세요.
- **`og.png` 는 1시간** — 메신저가 어차피 자기 쪽에 캐시하므로 짧게 잡아도 손해가 없고, 바꿨을 때 빨리 반영됩니다.
- `nosniff`, `Referrer-Policy`, `Permissions-Policy` 를 전체 경로에 적용합니다.

> **이 파일에 주석을 넣지 마세요.** JSON 에는 주석이 없어서 흔히 `"//"` 키를 쓰지만, Vercel 은 스키마에 없는 속성을 거부하고 배포가 통째로 실패합니다 (`headers[1] should NOT have additional property "//"`). 설명이 필요하면 이 README 에 적으세요.

**배포 주소가 정해지면 반드시 반영하세요.** 링크 미리보기의 `og:image` 는 절대 주소여야 해서, 도메인이 다르면 카드가 안 뜹니다.

```bash
node scripts/set-site-url.js https://실제-주소.vercel.app
node scripts/build-preview.js
git commit -am "배포 주소 변경" && git push
```

확인: `https://실제-주소/og.png` 가 브라우저에서 열려야 합니다.

**배포 전 미리 확인하기.** 개발용 `python3 -m http.server` 는 `/korea-uni` 를 `/korea-uni/` 로 넘기는데, Vercel 은 `trailingSlash: false` 라 반대로 넘깁니다. 한국 버전은 `../fonts/suit.css` 처럼 상대 경로로 자원을 걸기 때문에 이 차이가 실제로 문제가 될 수 있습니다. 배포본과 같은 규칙으로 띄워서 확인하세요.

```bash
node scripts/e2e/serve-vercel.js &                        # 8799 포트
BASE=http://127.0.0.1:8799/korea-uni node scripts/e2e/korea-e2e.js
```

파일 하나로 만들어 두면 메신저로 보내거나 아무 데나 올리기 편합니다.

## 폰트

전부 [SUIT](https://sun.fo/suit) 한 벌만 씁니다 (SUNN, SIL Open Font License 1.1). 이탤릭은 쓰지 않고, 굵기(400–800)와 크기·자간으로만 위계를 만듭니다.

CDN 을 못 씁니다 — 아티팩트는 CSP 로 외부 요청을 막고, `index.html` 을 더블클릭해서 여는 경우에도 CDN 은 동작하지 않습니다. 그래서 폰트를 파일 안에 data URI 로 심되, **앱 소스에 실제로 등장하는 글자만 남겨** 크기를 줄입니다.

```bash
# 원본 폰트를 받아 fonts/ 에 둔 뒤
curl -L -o fonts/SUIT-Variable.woff2 \
  https://raw.githubusercontent.com/sun-typeface/SUIT/main/fonts/variable/woff2/SUIT-Variable.woff2

python3 scripts/build-font.py     # 필요: pip install fonttools brotli
```

610KB → **112KB** (한글 662자, 가변축 wght 400–800 유지). 가변축을 100–900 그대로 두면 154KB, 정적 두 벌로 만들면 90KB 지만 500·600 굵기가 가장 가까운 값으로 튀어서 400–800 부분 인스턴싱을 택했습니다.

> **문구를 수정했으면 이 스크립트를 다시 돌리세요.** 서브셋에 없는 글자를 새로 쓰면 그 글자만 시스템 폰트로 떨어집니다.

## 링크 미리보기

카카오톡·인스타 등에 링크를 붙였을 때 뜨는 카드는 `index.html` 의 OG 메타 태그와 `og.png` 로 만들어집니다.

```bash
node scripts/build-og.js          # 필요: npm i -D playwright
```

`og:image` 는 크롤러가 직접 받아가야 해서 **절대 https 주소**여야 합니다. data URI 나 상대 경로로는 미리보기가 뜨지 않습니다. **배포 도메인이 바뀌면 `index.html` 의 `og:url` 과 `og:image` 주소를 같이 바꾸세요.**

카카오톡은 미리보기를 오래 캐시합니다. 바꿔도 그대로면 [카카오 디버거](https://developers.kakao.com/tool/debugger/sharing)에서 캐시를 초기화하세요.

`<script type="module">` 을 쓰지 않고 일반 `<script>` 로 순서대로 로드합니다. ES 모듈은 `file://` 에서 CORS 때문에 막혀서 더블클릭 실행이 안 되기 때문입니다. 외부 CDN·웹폰트·라이브러리도 쓰지 않습니다.

## 매칭이 동작하는 방식

선택지마다 8개 학교 점수를 직접 매기면 18 × 4 × 8 = 576개의 숫자를 손으로 관리해야 하고 일관성 유지가 불가능합니다. 대신 **성향 축 벡터** 방식을 씁니다.

1. **7개 양극 축**을 정의합니다 (커리큘럼 자유↔구조, 대도시↔자연, 소수정예↔대규모 등).
2. **각 학교에 축별 프로필**을 부여합니다. 예를 들어 브라운은 `curriculum -2`(오픈 커리큘럼), 컬럼비아는 `+2`(코어 커리큘럼).
3. **각 선택지에 축 가중치**를 답니다. 보통 주축 1개 + 보조축 1개.
4. 답변을 축별로 합산해 **사용자 벡터**를 만들고, 학교 벡터와 **코사인 유사도**로 순위를 냅니다.

### 정규화에서 중요한 두 가지

**축별 표준편차로 나눕니다** (이론상 최대치가 아니라). 어떤 축은 주축으로 2번만 나오는데 보조 가중치로는 12번 실립니다. 최대치로 나누면 그런 축은 실제 합계가 늘 0 근처에 눌려서, 그 축에 정체성이 걸린 학교가 아무리 답해도 안 올라옵니다.

**축별 편향(평균)을 뺍니다.** 네 선택지의 가중치 합이 0이 아닌 축이 있습니다 (이 문항 세트에서는 `curriculum` 이 −1.0, `scale` 이 +1.0 쏠려 있었습니다). 보정하지 않으면 아무렇게나 찍어도 그 축이 한쪽으로 기웁니다. 이 보정 하나로 학교별 1위 점유율 편차가 7.2~16.7% 에서 10.8~14.2% 로 줄었습니다.

**학교 행렬은 축마다 8개교 평균을 뺍니다.** "아이비는 대체로 도시적" 같은 공통 성분을 없애야 축이 학교 간 상대 차이만 재게 됩니다.

**코사인을 씁니다** (내적이 아니라). 학교 벡터 크기로 나누지 않으면 축 값이 극단적인 학교가 방향과 무관하게 유리해집니다.

### 퍼센티지

1위는 **84~97%** 사이에 놓입니다. 답변이 뚜렷할수록, 그리고 1위 학교와 방향이 잘 맞을수록 높아집니다. 2·3위는 1위와의 코사인 격차만큼 떨어지고, `P₁ > P₂ > P₃` 와 최소 2포인트 간격이 항상 보장됩니다.

## 내용 수정하기

질문 문구를 고치는 것만으로는 아무것도 깨지지 않습니다. **가중치나 학교 벡터를 고쳤다면 반드시 검증 스크립트를 돌리세요.**

```bash
node scripts/check-reachability.js   # 아이비 8곳
node scripts/check-korea.js          # 한국 30곳
node scripts/check-copy.js           # 화면에 나가는 문장 전부
```

검사 항목:

1. **도달성** — 무작위 답안지 4만 장에서 8개교가 모두 1위로 나오는가 (3% 미만이면 도달 불가, 30% 초과면 독식)
2. **현실적 사용자 시뮬레이션** — 일관되게 답하는 응답자 4만 명 기준 분포
3. **타당성** — 각 학교를 겨냥해 답하면 실제로 그 학교가 1위인가. **가장 중요한 항목입니다.** 하나라도 실패하면 그 학교를 대표하는 선택지가 부족하다는 뜻입니다.
4. **보정** — `cos_top` 과 뚜렷함의 실제 분포가 `js/scoring.js` 의 `CALIB` 구간과 맞는가
5. **엣지 케이스** — 전부 A / 전부 D / 번갈아 / 답이 완전히 상쇄된 경우

현재 상태 (모두 통과):

| 항목 | 결과 |
|---|---|
| 무작위 답안지 1위 점유율 | 10.8% ~ 14.2% (균등값 12.5%) |
| 현실적 사용자 시뮬레이션 | 8.3% ~ 15.0% |
| 겨냥 테스트 | **8/8 통과** |
| 1위 퍼센트 분포 | 최소 87 · 중앙 93 · 최대 97 |
| 단조성 `P₁>P₂>P₃` | 위반 0건 |
| 공유 링크 왕복 | 5만 회 무실패 |

**질문을 수정하면 `js/share.js` 의 `SHARE_VERSION` 을 올리세요.** 안 올리면 예전에 공유된 링크가 조용히 엉뚱한 결과를 보여줍니다. 버전이 다르면 앱이 "예전 버전 링크"라고 안내하고 다시 하도록 유도합니다.

### 모드를 추가하거나 문구를 고칠 때

- 화면 문구(라벨·안내문·공유 문구)는 전부 `js/data/copy.js` 한 곳에 있습니다.
- 질문 문구는 `questions.js` 의 `text.student` / `text.parent`, 선택지는 `label.student` / `label.parent` 입니다. **`weights` 는 모드별로 나누지 마세요** — 두 모드가 같은 기준으로 채점돼야 같은 답에 같은 결과가 나오고, 검증도 한 번만 돌리면 됩니다.
- 학교 해설도 `detail.student` / `detail.parent` 로 나뉘어 있고, `forParents` 는 학부모 모드에서만 보입니다.

**말투는 화면에 나가는 모든 글이 해요체입니다.** 두 모드의 차이는 주어("나" / "아이")뿐이고 문장 끝은 똑같이 갑니다. 반말(`~한다`, `~해`), 합니다체(`~합니다`), 평서형을 섞지 마세요 — 한 화면에 말투가 두 개 있으면 그것만 눈에 띕니다. 문항은 `~나요?` 로 묻고 선택지는 그 답을 해요체 한 문장으로 적습니다. (이 README 같은 개발 문서는 예외이고 합니다체를 씁니다.)

말투가 섞였는지 확인:

```bash
grep -rn "니다" index.html js/ --include=*.js --include=*.html | grep -v "^\S*: *[*/]"
```

문구를 고쳤으면 서브셋 폰트에 없는 글자가 생겼을 수 있으니 `python3 scripts/build-font.py` 를 다시 돌리세요. 문구만 고친 경우 `SHARE_VERSION` 은 올릴 필요가 없습니다 — 가중치가 그대로면 예전 링크도 같은 결과를 냅니다.

### 재정지원 정보 (2026년 8월 확인)

국제학생에게 **need-blind**(재정 상황이 합격 판단에 영향을 주지 않음)인 아이비는 **하버드·예일·프린스턴·다트머스·브라운** 다섯 곳입니다. 다트머스는 2022년, 브라운은 Class of 2029(2025년 가을 입학)부터 전환했습니다. **컬럼비아·코넬·유펜**은 need-aware 입니다. 여덟 곳 모두 합격한 학생에게는 산정된 필요액의 100%를 지원합니다.

> 이 표는 실제로 바뀝니다. 브라운은 2024년 1월에 1억 2천만 달러 모금을 마치고 전환을 발표했는데, 그 전에 만들어진 자료를 그대로 옮겨 쓰면 학부모에게 반대되는 정보를 보여주게 됩니다. 손댈 일이 있으면 각 학교 재정지원 페이지에서 직접 확인하세요.

학부모가 가장 먼저 묻는 정보이고 금전적 판단에 직결되므로, 정책이 바뀌면 `schools.js` 의 `forParents.aid` 를 갱신하세요. 화면에도 "지원 전에 각 학교 페이지에서 다시 확인하라"는 안내를 함께 띄웁니다.

## 공유 링크

답변 18개를 2비트씩 눌러 담아 5바이트로 만들고 base64url 로 인코딩합니다. 버전 태그와 체크섬을 붙여 최종 11자입니다.

```
#r=v1.GxsbGxAq
```

쿼리스트링이 아니라 **해시**를 쓰는 이유는 해시가 서버로 전송되지 않아 정적 호스팅의 리라이트 규칙에 영향을 받지 않고, `file://` 에서도 동작하기 때문입니다. 체크섬은 카카오톡·인스타에서 링크가 잘렸을 때 엉뚱한 결과 대신 안내 문구를 띄우기 위한 것입니다.

## 만든 것에 대해

학교별 성향 값은 각 학교의 널리 알려진 학제와 문화를 바탕으로 정했습니다 (브라운의 오픈 커리큘럼, 컬럼비아의 코어 커리큘럼과 맨해튼, 다트머스의 D-Plan과 시골 캠퍼스, 코넬의 7개 단과대, 유펜의 와튼, 프린스턴의 졸업논문, 예일의 레지덴셜 칼리지, 하버드의 규모). "좋다/나쁘다"가 아니라 "어느 쪽 성향이냐"만 나타냅니다.

각 학교와 아무 관련이 없는 비공식 팬 프로젝트입니다.
